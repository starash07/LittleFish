# LittleFish 安装包优化方案

基线版本：`1.5.2`  
方案日期：`2026-07-14`

## 1. 优化范围

本方案只针对 LittleFish 独立版的构建、安装、更新和卸载流程，不修改 SeaS，也不依赖 SeaS 目录中的任何文件。

保留以下产品原则：

- 继续提供 Windows x64 自包含安装包，目标电脑无需预装 .NET。
- 默认安装到当前用户目录，不要求管理员权限。
- 更新时保留阅读设置、进度和书签。
- 卸载默认保留用户设置，只有用户明确确认后才删除。
- 安装、更新和卸载只处理目标安装目录中的 LittleFish，不影响其他便携副本或 SeaS 内置版本。

## 2. 当前基线与截图问题

优化前的 `1.5.2` 构建基线：

| 项目 | 当前值 |
| --- | ---: |
| 最终安装包 | 约 `228.03 MiB` |
| 主程序自包含发布目录 | 约 `160.00 MiB` |
| 轻量卸载器 | 约 `12.05 MiB` |
| 安装后总占用 | 约 `172.05 MiB` |

截图中的问题按当前代码重新核对如下：

| 问题 | 当前状态 | 本方案处理方式 |
| --- | --- | --- |
| 完整安装包被复制一份作为卸载器，安装后超过 380 MiB | `1.5.2` 已解决 | 保留轻量卸载器，并增加体积回归检查，防止旧逻辑复发 |
| 不比较版本号，旧安装包可覆盖新版本 | 已解决 | 已区分升级、同版本修复和禁止降级 |
| 选择 Program Files 后没有权限，安装失败 | 已解决 | 已引入当前用户/所有用户安装范围、按需 UAC 提权和设置迁移 |
| 更新时取消快捷方式选项，不删除已有快捷方式 | 已解决 | 已按电脑现状初始化，并按勾选状态同步创建或删除 |

| 项目 | 优化后 |
| --- | ---: |

| 安装内容总量 | `170.47 MiB` |
| 轻量卸载器 | `10.47 MiB` |
| 安装包降幅 | 约 `37.6%` |

## 3. 目标

### 3.1 体积目标

- 第一目标：最终安装包不超过 `160 MiB`。
- 保底目标：相对 `228.03 MiB` 基线至少下降 `20%`。
- 安装后占用保持在 `175 MiB` 以内，不因安装器改动反弹。
- 不通过改成依赖系统 .NET、激进裁剪 WPF 或删除必要运行库来换取体积。

上述安装包目标是预期值，最终以干净环境重新打包后的实测结果为准。

### 3.2 行为目标

- 已安装版本低于安装包版本：显示“升级”，允许覆盖更新。
- 已安装版本等于安装包版本：显示“修复”，允许重新写入程序文件。
- 已安装版本高于安装包版本：明确提示已安装较新版本，并阻止降级覆盖。
- 默认用户目录安装不弹 UAC。
- 选择 Program Files 等受保护目录时，安装器能够请求管理员权限并完成安装。
- 用户取消 UAC 时不写入任何程序文件、快捷方式或注册表项。
- 更新页面上的快捷方式勾选状态与电脑当前状态一致，完成后也与用户选择一致。

## 4. 第一阶段：修复截图中的四项问题

### 4.1 保持轻量卸载器并建立防回归检查

现有 `LittleFish_Uninstall.exe` 已经替代“复制完整安装包作为卸载器”的旧逻辑，本阶段不重写卸载器，只做以下加固：

1. 构建脚本验证安装 payload 中存在轻量卸载器。
2. 验证轻量卸载器不包含 `payload.zip`。
3. 验证安装目录内不存在第二份 `LittleFish_Setup*.exe`。
4. 打包结束输出三项实测值：安装包大小、payload 解压大小、卸载器大小。
5. 增加上限检查：卸载器超过 `20 MiB` 或安装后总量超过 `175 MiB` 时构建失败。

### 4.2 增加版本比较和安装模式

将当前仅依赖“注册表里有没有安装路径”的判断改成明确的安装状态：

```text
FreshInstall      未检测到已安装版本
Upgrade           已安装版本 < 安装包版本
Repair            已安装版本 = 安装包版本
DowngradeBlocked  已安装版本 > 安装包版本
```

实现要点：

1. 优先读取卸载注册表中的 `DisplayVersion`。
2. 注册表版本缺失或格式无效时，再读取安装目录中 `LittleFish.exe` 的产品版本。
3. 使用标准 `Version` 数值比较，不使用字符串排序。
4. 降级默认直接阻止，不提供容易误触的“继续覆盖”按钮。
5. 同版本安装显示“修复 LittleFish”，保留设置并重新同步程序文件、快捷方式和卸载信息。
6. 注册表补充 `VersionMajor`、`VersionMinor`、`InstallDate` 和 `EstimatedSize`，方便 Windows 正确展示版本与占用。

界面文案同步调整：

| 状态 | 标题 | 主按钮 |
| --- | --- | --- |
| 首次安装 | 安装 LittleFish | 安装 |
| 升级 | 将 LittleFish 从 x 升级到 y | 升级 |
| 同版本 | 修复 LittleFish y | 修复 |
| 降级 | 已安装较新版本 x | 关闭 |

### 4.3 解决 Program Files 权限和设置写入问题

当前设置文件位于程序目录下的 `settings.json`。即使安装器通过 UAC 成功写入 Program Files，主程序以普通权限运行后仍可能无法保存设置。因此权限问题必须同时调整安装范围和设置存储。

建议采用两种安装范围：

| 安装范围 | 默认路径 | 提权 | 卸载注册表 | 快捷方式 |
| --- | --- | --- | --- | --- |
| 当前用户 | `%LOCALAPPDATA%\Programs\LittleFish` | 不需要 | `HKCU` | 当前用户桌面和开始菜单 |
| 所有用户 | `%ProgramFiles%\LittleFish` | 需要 UAC | `HKLM` | 公共桌面和公共开始菜单 |

安装流程：

1. 用户保持默认路径时，继续按当前用户模式安装。
2. 用户选择 Program Files、Windows 等受保护目录时，切换为所有用户模式。
3. 点击安装后使用 `runas` 重新启动同一个安装器，并通过参数传递安装路径和快捷方式选项。
4. 提权进程重新校验所有参数，不信任父进程直接传入的路径。
5. UAC 被取消时回到选项页并显示提示，不创建半成品目录。
6. 所有用户模式写入 HKLM，卸载器按安装范围请求提权并删除对应注册表与公共快捷方式。

设置文件迁移方案：

- 正式安装版统一改用 `%LOCALAPPDATA%\LittleFish\settings.json`。
- 启动时若新位置没有设置，而旧安装目录存在 `settings.json`，自动迁移一次。
- 非安装的便携运行模式继续使用程序目录旁的 `settings.json`，保持现有便携特性。
- 卸载默认保留 `%LOCALAPPDATA%\LittleFish`；用户明确选择删除设置时只删除当前用户的数据。
- 所有用户卸载不扫描或删除其他 Windows 用户的个人设置。

为区分正式安装和便携运行，可通过安装目录中的 `.littlefish-manifest.txt` 或新增的安装元数据文件识别。

### 4.4 同步快捷方式状态

进入更新或修复页面时：

1. 检查当前安装范围对应的桌面快捷方式是否存在。
2. 检查当前安装范围对应的开始菜单 `LittleFish` 目录是否存在。
3. 用检查结果初始化两个复选框，不再始终默认勾选。

安装结束时采用“同步”语义：

| 当前状态 | 用户选择 | 结果 |
| --- | --- | --- |
| 已存在 | 勾选 | 更新目标、图标和工作目录 |
| 已存在 | 取消 | 删除该快捷方式 |
| 不存在 | 勾选 | 创建快捷方式 |
| 不存在 | 取消 | 保持不存在 |

只删除 LittleFish 自己的固定路径快捷方式，不扫描或删除用户自行创建、重命名的快捷方式。

## 5. 第二阶段：减小安装包

按风险从低到高执行：

1. 安装器单文件发布增加 `EnableCompressionInSingleFile=true`。
2. 明确设置 `PublishReadyToRun=false`，避免生成非必要的预编译体积。
3. 将安装器的 WinForms `FolderBrowserDialog` 替换为 .NET 8 WPF `Microsoft.Win32.OpenFolderDialog`。
4. 从安装器项目移除 `UseWindowsForms`，减少外层安装器携带的 WinForms 运行库。
5. 主程序继续保留 WinForms，因为托盘图标和颜色选择器仍在使用；本轮不为体积强行重写这些功能。
6. 保持主程序多文件自包含发布后再压入 payload，不对 WPF/WinForms 主程序启用高风险裁剪。
7. 打包完成后默认删除 `dist/installer` 中间目录，增加 `-KeepBuildArtifacts` 参数供排错时保留。

每一步分别打包并记录大小，避免多个变量同时变化后无法判断收益来源。

## 6. 第三阶段：安装失败回滚

当前安装是直接覆盖目标目录，发生文件占用、磁盘不足或注册表写入失败时可能留下部分新文件。建议改成事务式流程：

1. 将 payload 解压到安装目录同磁盘的临时 staging 目录。
2. 校验主程序、卸载器、文件清单和 payload 哈希。
3. 关闭目标安装目录中的 LittleFish 进程。
4. 将旧版受管文件移动到 rollback 目录。
5. 将 staging 内容移动到正式目录。
6. 同步快捷方式并写入卸载注册表。
7. 全部成功后删除 rollback；任何一步失败则恢复旧文件和旧注册表状态。

`settings.json` 或迁移后的用户设置目录始终不进入覆盖和回滚删除清单。

## 7. 完整性与发布质量

本轮可以先做不依赖证书的完整性检查：

- 构建时生成 payload 的 SHA-256。
- 安装前校验内嵌 payload，校验失败时停止安装。
- 最终安装包生成同名 `.sha256` 文件供发布页使用。
- 检查 EXE 的 `ProductVersion`、`FileVersion` 和文件名版本一致。

代码签名需要可信证书，可作为独立发布工作处理。签名完成后应同时签署主程序、卸载器和最终安装包。

## 8. 代码整理建议

安装器窗口代码已经承担界面、版本判断、文件部署、注册表、快捷方式和卸载逻辑。实施时建议拆出以下单元，降低后续修改风险：

```text
InstallDiscovery       查找 HKCU/HKLM 安装信息并比较版本
InstallScopeResolver   判断当前用户/所有用户范围和提权需求
PayloadInstaller       解压、校验、覆盖和回滚
ShortcutManager        检查、创建和删除快捷方式
UninstallRegistry      读写 HKCU/HKLM 卸载信息
SettingsLocation       正式安装/便携模式的设置路径与迁移
```

窗口代码只负责展示状态、收集选项和调用上述服务。

## 9. 验收矩阵

### 9.1 版本行为

- 未安装 LittleFish：进入首次安装。
- 已安装 `1.5.1`，运行 `1.5.2`：进入升级。
- 已安装 `1.5.2`，运行 `1.5.2`：进入修复。
- 已安装 `1.5.3`，运行 `1.5.2`：阻止降级，程序文件不变。
- 注册表版本损坏但 EXE 版本有效：使用 EXE 版本判断。

### 9.2 权限与路径

- 默认 LocalAppData 安装不弹 UAC。
- Program Files 安装弹 UAC，确认后安装成功。
- UAC 取消后没有残留目录、快捷方式和注册表项。
- Program Files 安装后，以普通权限运行仍能保存字号、行高、进度和书签。
- 中文路径、带空格路径和磁盘根目录选择均能正确归一到 `LittleFish` 子目录。

### 9.3 快捷方式

- 对桌面和开始菜单分别覆盖“存在/不存在”乘以“勾选/取消”的四种组合。
- 升级时取消勾选会删除已有快捷方式。
- 修复时保持勾选会刷新快捷方式目标，不产生重复项。
- 卸载只删除对应安装范围内的 LittleFish 快捷方式。

### 9.4 更新、回滚与共存

- 更新保留设置、阅读进度和书签。
- 模拟文件占用导致更新失败，旧版本仍可启动。
- 只关闭目标安装路径下的 `LittleFish.exe`。
- 其他路径的 LittleFish 便携副本不被关闭或删除。
- 整个实现和测试过程不读写 SeaS 项目目录。

### 9.5 体积与产物

- 最终安装包达到体积目标或记录未达标原因。
- 安装目录只包含一份约 12 MiB 的轻量卸载器，不包含完整安装包副本。
- 安装后总量不超过 `175 MiB`。
- `ProductVersion`、注册表 `DisplayVersion` 和安装包文件名一致。
- 打包成功后源码目录中不存在临时 `payload.zip`。
- 默认只保留 `dist/setup` 成品，不保留 `dist/installer` 中间目录。

## 10. 推荐实施顺序

1. 先抽离版本比较和快捷方式管理，解决更新语义。
2. 调整设置存储和迁移，再实现当前用户/所有用户安装范围与 UAC。
3. 加入 staging、回滚和 payload 完整性校验。
4. 开启单文件压缩、移除安装器 WinForms 并测量体积。
5. 执行完整验收矩阵，最后生成新的正式安装包。

这个顺序确保每一阶段都能独立验证，也避免在设置仍写入程序目录时过早开放 Program Files 安装。
